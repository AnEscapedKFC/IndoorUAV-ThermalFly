# 会议室阻塞体素的历史 RGB-D 回投与定向补看

入口是接入层的 `run.py flight window`。每一架次新建独立的历史缓存，从本架次的预扫开始，记录同步 RGB-D、米制相机位置、包含机体姿态和实际云台角的光学轴、内参与俯仰角。预扫沿用原有模拟传感器水平环视，任务开始后的侧向补看使用四旋翼动力学执行机体偏航。实验使用 PlanarGS RGB 30k 原生平面深度离线碰撞图，在线观测沿用 gsplat 期望深度。地图文件的 SHA-256 应为 `0dec30b75412d749b4354ea3f37444834244051a547d3a7beb1fab55a95dfd7f`。

## 航点检查

每个运动候选分别检查机体倾斜、平移和制动的扫掠包络。遇到证据为零的 6.5 厘米体素时，将其八个角投回最多 192 个已保存的 RGB-D 视角。相邻留存帧至少有 1.5 厘米位移或 2° 旋转。每个 4×4 像素块保留 RGB 均值和原始深度极值，保留缺测信息。体素投影膨胀包含 1 厘米位置和 0.75° 姿态误差，距离余量为 4 厘米加体素光轴深度的 2.5%。整块投影须位于画面内。深度下界必须超过膨胀体素的远侧，深度变化在允许范围内，颜色边缘处收紧深度一致性条件。

两个满足条件的视角需要相差至少 2.5 厘米或 6° 光轴方向。历史中有可靠表面与待证体素相交时，否决本次历史放行。方向不同但相机中心相近的观测仍可能共享 3DGS 系统深度偏差。已有正表面体素不会通过历史回投清除。每次只更新获得证据的未知体素，后续路径继续逐段检查。

## 定向补看

当全部候选被拦截，飞控收集最先阻塞各候选的体素。对候选机体航向和机械俯仰角，绕机体中心旋转实测镜头安装偏移，再投影体素八角，优先覆盖完整体素，同等覆盖时优先只动云台。同一位置对同批体素最多尝试两个几何视角，可见角点为零时直接保留未知。机体速度在 0.035 米/秒以内时，先朝该方向调整云台，俯仰范围 −60° 至 +30°。阻塞方向偏左或偏右且仍有未知格时，以当前机体位置为定点执行偏航，观察后恢复任务视角。起点预扫后若静止包络仍存在未知，首个导航航点下发前也执行这个流程。持续表面冲突保留原有拒飞处理。

原地偏航及回转可扫过未知体素。已知占据表面、动力学每步的机体扫掠碰撞检测、任务时限继续生效，位置漂移超过 4 厘米时终止补看。只对原地偏航豁免离线已知自由网格的终止检查，实际越界状态仍逐帧记录，并参与原评分。平移仍需通过原有完整检查。补看的视频、状态和时间计入本架次，回归任务视角后从新观测重新规划。

## 复跑

从 `indooruav_rgb_bridge/grounding_study` 在独立终端启动策略服务，并在运行终端执行第二条命令。默认结果位于 `metric_flight/results/observation_window_unknown_views/<case>/`，已有完整回合会跳过。复测下列 13 个原先未自主完成的回合。

```bash
python -B ../bridge_client.py --socket ../runtime/grounding-study.sock serve -- ../scripts/model_worker.sh
./launch.sh run.py flight window --cases chair_far chair_north desk_fresh desk_new level_diagonal level_east level_fresh level_new level_west outlet_east outlet_fresh outlet_west overview_east
```

`blocked_views.json` 保存本回合留存过的帧数、由历史证据释放的格子和见证帧编号、补看目标、执行阶段、实际偏航、位置漂移和补看后剩余未知格。每个决策对应的拒绝原因和体素索引在 `decisions.json`。沿用 [一秒观察及自主完成规则](OBSERVATION_WINDOW.md)，对于改变了画面的回合应复核新录像后再评分。RGB 与热红外录像保存在本地。

# 根据指令协调机体高度与云台俯仰

实验使用会议室 RGB 3DGS 的模拟相机、四旋翼动力学和冻结的 IndoorUAV-Agent。模型读取 RGB 和带方位提示的指令，输出航点候选。接入层使用候选在目标方位上的进度、当前 RGB 检测、历史 RGB-D 表面记录和实际相机标定，生成受安全检查的航点与独立的云台指令。每次从空的目标观测记录开始。飞行入口禁止读取专家记录，没有新增训练。热红外由同一物理时刻的标定外参渲染，用于录像。

本轮 13 次记录的逐次数据、严格完成率及失败画面见[飞行结果报告](coordinated_results/REPORT.md)。

## 三项修改

1. 预扫描、初始姿态、航行和悬停的云台机械俯仰均限于 −60° 至 +30°。飞行中以 2 Hz 从 RGB 整机检测框中心更新瞄准方向，以 20 Hz 按实测姿态重投影，云台每秒最多转动 12°。机体用当前与历史 RGB-D 估计的表面位置和预测的水平距离，算出与指令相容的相机高度。高度差较大时降低前进速度。已到达合适视线时仍会继续检查画幅和部件。机械角以机体为参考，光轴仰角和相机指向被观测表面的仰角以世界水平面为参考。
2. 画幅使用完整被观测物体的检测框宽×高除以图像面积。20%–60% 含两端，低于 20% 记为过小，高于 60% 记为过近。下沿出风口有独立的 RGB-D 视线测量，面积分母始终是整幅 640×480 RGB，面积分子始终是整台空调的框。居中要求框中心横纵坐标均在归一化的 0.30–0.70 范围内，框不能贴边裁切。目标证据由冻结检测器、SlimSAM 和 RGB 部件分界估计给出。
3. 预扫描返回初态、首个航点下发前，用同一规划包络和实际机体姿态查询局部深度占据图，记录表面与未知格子数量。存在冲突时，用已有扫描方向优先复看争议区域，机体保持悬停，随后回到相同初态重查。仍有冲突即结束该架次，保留首帧、视频与诊断，发出的导航航点数为零。预扫使用接入层的传感器水平扫描自由度，完成后通过模拟器 reset 恢复任务首帧，预扫时间单列。起点机体包络继承模拟器已放置机体的初始空闲先验，只播种一次。后续深度可以推翻该先验；此检查不能独立证明盲区内没有障碍。启动通过后，每个运动候选还需通过动态包络和制动检查。

## 指令与验收

| 指令表达 | 观测参考 | 允许的实际视线仰角 |
|---|---|---|
| 平视空调，完整观察正面 | RGB-D 空调整机可见表面中位点 | −8° 至 +8° |
| 从下方仰视空调出风口 | RGB-D 出风口区域中位点 | +12° 至 +32° |
| 从上方俯视笔记本，观察屏幕与键盘 | RGB-D 笔记本可见表面中位点 | −48° 至 −18° |

这些角度是对本轮语言方向的工程化解释。不同物体可使用同一方向，指令没有给出绝对高度、距目标的米数或云台设定角。未指定方向时，控制器根据当前视线与机械余量分担高度。动作选择没有读取目标世界坐标标签。部件外观分界使用有限的类别先验，尚未验证开放词汇泛化。

严格完成需连续三次决策满足构图、视线、可见部件和跨视角一致性，再主动停稳两秒。悬停期间独立采样四张实际 RGB-D，每张都要有合格的检测框、部件和观察角，全程零碰撞、零越界。悬停位置偏移不超过 0.12 米，末半秒采样速度不超过 0.10 米/秒。末帧单独重跑 RGB 检测。保留拒飞、目标丢失、碰撞、越界和未停稳的全部架次。

历史命令 `flight history` 保留上一版本的对照协议。本轮三项规则统一由 `flight coordinated` 启用。

## 复跑

在 indooruav_rgb_bridge 目录启动模型服务。

```bash
python -B bridge_client.py --socket runtime/grounding-study.sock serve -- scripts/model_worker.sh
```

在 grounding_study 目录运行以下命令。完整回合按名称跳过，临时回合完成录像全解码校验后原子发布。复跑到空结果目录可先移走本地同名结果。

```bash
./launch.sh run.py flight coordinated
./launch.sh metric_flight/coordinated_review.py
./launch.sh -m unittest discover -s metric_flight -p 'test_*.py'
```

使用 `--cases level_diagonal outlet_diagonal desk_east` 可选择三个代表架次。完整英文指令和起点定义见 [history_flight.py](history_flight.py)。每个回合在 `metric_flight/results/coordinated_inspection/<case>/` 保存预扫描证据、轨迹、原模型与实际航点、历史观测、实际框与视线及同步录像。独立复核输出见 [结果数据](coordinated_results/results.json)、[末帧对照](coordinated_results/end_views.jpg) 和 [高度、云台与画幅曲线](coordinated_results/flight_profiles.png)。原始视频保存在运行机器。

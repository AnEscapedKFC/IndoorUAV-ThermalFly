# 一秒持续观察的会议室动力学实验

## 当前复飞规则

从第一次经目标类别和实例关联的检测开始维护前景特征。新检测要通过实例空间关联，历史框须以当前 RGB 前后向光流、世界坐标深度和特征覆盖复核。两种观测都可进入悬停。控制器在一秒窗口的首、中、末帧以 2 Hz 检查目标，要求有效框面积中位数在 10%–50%、居中、完整、部件与任务视线合格，悬停全过程漂移至多 12 cm。允许一次中间缺测和单帧下浮至 8%；首末须有证据。末帧缺证时每 0.5 秒重取当前 RGB-D，最多多等 1 秒；明确要求两秒的任务仍使用两秒窗口。

在完成预扫描和针对冲突格的复查后，如只有 2.5 cm 附加余量接触表面，可开始评估航点。原表面格保留在图中，平移、转动时仍逐姿态检查 5 cm 安全包络。飞行时，地图覆盖告警触发一秒制动和深度复核；速度降至 0.10 m/s 以内、裸机体仍在已知空间、在线静止包络证实空闲才允许重新规划。连续告警不会反复获得新的制动宽限。房间坐标文件的米制外包盒用作本组实验明确的机体中心飞行边界，动力学逐子步检查实际碰撞与该边界。每个回合的 `safety_events.json` 单列地图覆盖告警、显式边界违规、碰撞；`hold_attempts.json` 保存观测来源、中位数、复核时长和位移。

在 `indooruav_rgb_bridge/grounding_study` 下运行，结果位于 `metric_flight/results/observation_window_reviewed/<case>/`。

```bash
python -B ../bridge_client.py --socket ../runtime/grounding-study.sock serve -- ../scripts/model_worker.sh
# 在第二个终端运行
./launch.sh run.py flight window --cases chair_far chair_north desk_fresh desk_new level_diagonal level_east level_fresh level_new level_west outlet_east outlet_fresh outlet_west overview_east
```

## 历史基线（20%–60%）


本轮使用固定的 IndoorUAV-Agent、会议室 RGB 与热红外 3DGS、原四旋翼模拟器和 640×480 第一视角。动力学、检测置信阈值、云台硬限位、局部运动包络、静止起点复查、观察方向范围与 20%–60% 的整机检测框面积要求沿用上一轮。飞行不读专家轨迹、不训练网络。同步热红外用于录像；控制使用 RGB、深度和标定姿态。

本轮逐架次判定、第一视角证据及同起点比较见[飞行实验结果](window_results/REPORT.md)。

## 完成条件

一次决策中的目标框须完整、中心横纵坐标均落在画面 30%–70% 范围内，语言所需部件可辨，具备此前视角的边缘与深度一致性。平视空调取整机表面视线 −8° 至 +8°，仰视出风口取该部件视线 +12° 至 +32°，俯视笔记本取 −48° 至 −18°。沙发要求全貌、两端、靠背与坐面，门口黑色扶手椅要求椅体、靠背和可见坐面。沙发与椅子指令均未指定上下角度。

第一张高可信合格帧立即请求悬停和制动安全检查。悬停期间每半秒从实际 RGB-D 更新一次观测。一秒内相对开始位置的最大位移须不超过 0.12 米。明确要求悬停两秒的指令仍查两秒。后续直接检测丢失时，从合格帧的目标前景特征在新 RGB 图上做双向光流匹配，用同一世界坐标系中的实测深度验证对应点，再估计二维变换和新的框。每张新图都重验当前构图、部件与视线。失败的尝试恢复导航，保留每次尝试的物理位置与观测来源。

- **观察完成**要求在实际飞行中取得并保持符合指令的画面。对自主确认的回合检查起始、+0.5 秒和 +1.0 秒的照片和目标身份。对近距漏检的回合，由助手在原始 RGB 上分别补画每张图的框，使用该帧对应深度及相机外参复核视线，全段 20 Hz 状态复核位移；证据只参与离线计分。在静态拒飞、未能抵近、越出已知空间、发生碰撞或缺乏合格画面的情况下记录失败。
- **自主完成**要求飞行中的实时检测或 RGB-D 跟踪已确认完整窗口、主动停止，且画面事后核验通过。仅在离线复核中满足标准的回合只计入观察完成。旧版两秒严格成绩保留在独立结果目录。

## 任务与起点

平视空调、仰视出风口、俯视笔记本复测上一轮的 12 个任务/起点组合。沙发采用面向整张沙发的全貌指令，在东、西、斜向及较远起点测试。用户核定门口凳子为门旁单独的黑色带扶手椅。飞行起始通过当前 RGB 同时识别椅子与门，将椅子候选的 RGB-D 位置与门比较，拒绝含糊的关联；飞行中使用本次已见的实例位置关联新的候选框。北侧、东侧及较远起点均使用相同指令。另为每类指令设置一个冻结参数后的补充位置，两条空调指令从相同的新位置起飞。具体坐标和英文指令列在 [history_flight.py](history_flight.py)。

## 重现

在 indooruav_rgb_bridge 目录启动本地模型服务。然后在 grounding_study 目录执行以下命令。

```bash
./launch.sh run.py flight window
./launch.sh metric_flight/window_review.py
./launch.sh -m unittest discover -s metric_flight -p 'test_*.py'
```

飞行入口支持用 `--cases` 按名称选择任务。每架次完整记录位于 `metric_flight/results/observation_window/<case>/`，含三个经过全解码核验的 MP4、20 Hz 轨迹、每次观测的原始 RGB 与同步毫米深度及相机位姿、控制器请求和各次悬停尝试。新结果独立保存，已完成架次按目录跳过。离线图框与核验判断在 `window_results/annotations.json`。若在不同权重或渲染条件下生成新的视频，应复查该次图像并重新标注。
